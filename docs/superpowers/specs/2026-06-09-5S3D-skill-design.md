# 五看三定 AI 战略洞察助手 — 设计规格

> 基于华为IPD战略执行（DSTE）体系的"五看三定"方法论，设计一个多智能体AI Skill，
> 帮助研发团队在Charter（新产品启动）阶段完成80%的资料搜集与初筛工作。
>
> 实现形态：Claude Code Skill（slash command `/5s3d`），一键自动输出完整报告
> 输出格式：结构化Markdown报告，可直接用于Charter汇报

**版本**: v1.0
**日期**: 2026-06-09
**设计者**: Jian Wang (通过 brainstorming 流程)

---

## 1. 整体架构

### 1.1 四层架构

```
用户输入: "新产品方向（如：高功率密度轴向磁通电机在低空经济中的应用）"
        │
        ▼
┌──────────────────────────────────────────────────┐
│ Layer 1: 五看并行 (5个Agent并行搜+析)            │
│  看趋势 · 看对手 · 看客户 · 看自己 · 看机会     │
│  → 各输出结构化JSON数据                          │
└──────────────────┬───────────────────────────────┘
                   ▼
┌──────────────────────────────────────────────────┐
│ Layer 2: 交叉验证 (1个Synthesis Agent)           │
│  去重 → 矛盾识别 → 跨模块关联 → 优先级排序      │
└──────────────────┬───────────────────────────────┘
                   ▼
┌──────────────────────────────────────────────────┐
│ Layer 3: 三定顺序 (3个Agent递进决策)             │
│  定目标 → 定策略 → 定计划                        │
│  (前一个输出是后一个的输入)                      │
└──────────────────┬───────────────────────────────┘
                   ▼
┌──────────────────────────────────────────────────┐
│ Layer 4: 报告生成器                               │
│  完整Markdown报告 → 保存至 docs/ 目录           │
└──────────────────────────────────────────────────┘
```

### 1.2 技术路线

- 使用 `superpowers Workflow` 编排全过程
- Layer 1：`parallel()` 并行启动5个Agent
- Layer 2-3：`pipeline()` 顺序阶段
- Layer 4：描述型Agent最终合成
- 每个Agent通过 `schema` 参数约束输出JSON结构

---

## 2. 输入层

用户输入一个新产品方向（自然语言描述），由入口Agent拆解为**搜索意图三元组**：

| 维度 | 说明 | 示例 |
|------|------|------|
| **技术域** | 涉及的核心技术方向 | 轴向磁通电机、高功率密度、油冷 |
| **应用域** | 目标市场/应用场景 | 低空经济、eVTOL、无人机 |
| **约束条件** | 认证/成本/时间等约束 | 适航认证、量产成本、研发周期 |

这三个维度传递给Layer 1所有Agent作为搜索和分析的种子词。

## 3. 五看并行模块（Layer 1）

### 3.1 看趋势 Agent（Trend）

**目的**: 定位技术生命周期阶段，识别政策与标准环境

**搜索策略**:
- WebSearch：`{技术域} + 趋势/发展/前沿` 最新1-2年信息
- WebSearch：`{技术域} + 政策/标准/法规`
- WebSearch：`{技术域} + 专利 + 论文` 近5年趋势
- WebFetch：对最有价值的文章/报告进行深度提取

**输出Schema**:
```json
{
  "technology_lifecycle": "导入期 | 爆发期 | 成熟期 | 衰退期",
  "lifecycle_evidence": ["专利年申请量趋势", "学术论文发表趋势", "投融资事件"],
  "policy_landscape": [
    {"region": "中国", "policy": "政策名称", "impact": "利好/限制/中性"}
  ],
  "standards": [
    {"standard": "GB/ISO/航空级", "status": "已发布/制定中", "relevance": "强制/参考"}
  ],
  "key_trends": [
    {"trend": "趋势描述", "confidence": "高/中/低", "source_url": "来源"}
  ]
}
```

### 3.2 看对手 Agent（Competitor）

**目的**: 识别赛道内主要参与者，提取公开技术参数进行对标

**搜索策略**:
- WebSearch：`{技术域} + 龙头企业/领导者`
- WebSearch：`{技术域} + startup + 融资`
- WebSearch：品牌名 + `技术白皮书/参数/规格`
- WebFetch：竞品官网/白皮书深度提取

**输出Schema**:
```json
{
  "top_players": [
    {
      "name": "YASA / 某公司",
      "type": "巨头 | 初创 | 跨界",
      "region": "欧洲/中国/北美",
      "funding": "最近融资轮次+金额(初创)",
      "key_products": ["P400 R", "其他产品名"],
      "technical_params": {
        "power_density": {"value": 15, "unit": "kW/kg"},
        "efficiency": {"value": 95, "unit": "%"},
        "cooling": "油冷/水冷/风冷",
        "weight": {"value": 28, "unit": "kg"},
        "voltage": {"value": 800, "unit": "V"}
      },
      "target_market": "eVTOL / 乘用车 / 工业",
      "source_urls": ["白皮书URL", "官网URL"]
    }
  ],
  "emerging_threats": ["近2年获得大额融资的初创公司名"],
  "competitive_landscape_summary": "竞争格局一句话总结"
}
```

### 3.3 看客户 Agent（Customer）

**目的**: 识别终端客户的真实痛点和未被满足的需求

**搜索策略**:
- WebSearch：`{应用域} + 痛点/挑战/瓶颈`
- WebSearch：`{技术域} + 客户需求 + 技术指标要求`
- WebSearch：行业论坛/研讨会纪要/技术演讲
- WebFetch：重点行业报告摘要提取

**输出Schema**:
```json
{
  "pain_points": [
    {
      "pain": "散热困难/高频振动/系统减重遭遇瓶颈",
      "frequency": "高/中/低（被提及频次）",
      "source_type": "招投标/技术演讲/研报/论坛",
      "quotes": ["客户原话或接近原话的描述"]
    }
  ],
  "value_proposition_match": {
    "what_customers_want": ["降本20%", "性能提升30%"],
    "what_customers_willing_to_pay": "按价值定价/按成本定价",
    "top_priority": "当前客户最看重的单一指标"
  },
  "procurement_signals": [
    {"signal": "招标/采购意向", "source_url": "来源"}
  ]
}
```

### 3.4 看自己 Agent（Self）

**目的**: 对标竞品和客户需求，识别自身能力差距

**搜索策略**: 
- 无外部搜索（不需要WebSearch/WebFetch）
- 基于"看对手"和"看客户"的输出进行对标分析
- 如果用户输入时附带了自身技术能力描述，则进行精准差距分析
- 否则输出标准"待补充"模板

**输出Schema**:
```json
{
  "self_capabilities": {
    "provided_by_user": false,
    "description": "若用户提供了能力描述则填入",
    "gaps": []
  },
  "capability_gap_matrix": [
    {
      "dimension": "功率密度",
      "competitor_benchmark": "15 kW/kg (YASA)",
      "customer_requirement": "≥12 kW/kg",
      "our_capability": "10 kW/kg（待补充）",
      "gap": "2-5 kW/kg",
      "gap_type": "技术储备 | 工艺制造 | 供应链 | 资金",
      "criticality": "高/中/低"
    }
  ],
  "strategic_assets": ["自有关键技术/专利/客户关系"],
  "resource_bottlenecks": ["某工艺能力/特定供应链依赖"]
}
```

### 3.5 看机会 Agent（Opportunity）

**目的**: 基于前四看，识别机会点并估算市场规模

**搜索策略**:
- WebSearch：`{应用域} + 市场规模 + TAM + forecast`
- WebSearch：`{应用域} + CAGR + market size`
- 参考"看客户"和"看对手"的数据

**输出Schema**:
```json
{
  "opportunity_funnel": [
    {
      "opportunity": "低空经济eVTOL专用高功率密度电机",
      "ansoff_quadrant": "新市场-现有产品 | 新市场-新产品 | ...",
      "tam": {"value": 500, "unit": "亿美元", "year": 2030, "source": "沙利文报告"},
      "sam": {"value": 80, "unit": "亿美元", "note": "可服务部分"},
      "som": {"value": 5, "unit": "亿美元", "note": "可达部分"},
      "attractiveness": "高/中/低",
      "win_probability": "高/中/低",
      "priority_rank": 1
    }
  ],
  "market_growth_rate": "CAGR XX% (年份区间)",
  "summary_verdict": "这块肉够不够大的一句话结论"
}
```

### 3.6 并行调度方式

5个Agent通过 `Workflow.parallel()` 同时启动，互不等待。

```
Workflow.parallel([
  Agent("看趋势", prompt=..., schema=TREND_SCHEMA),
  Agent("看对手", prompt=..., schema=COMP_SCHEMA),
  Agent("看客户", prompt=..., schema=CUST_SCHEMA),
  Agent("看自己", prompt=..., schema=SELF_SCHEMA),
  Agent("看机会", prompt=..., schema=OPP_SCHEMA),
])
```

每个Agent独立使用WebSearch做广度搜索，WebFetch做关键来源深度提取。
搜索结果通过schema约束的结构化JSON输出，供Layer 2可靠解析。

## 4. 交叉验证层（Layer 2）

这是方案的核心创新——解决纯并行架构的信息孤岛问题。使用1个Synthesis Agent处理5个"看"的输出。

### 4.1 去重（Deduplication）

多Agent可能找到相同实体，按实体名称合并：

```
输入: 看对手 → {"name": "YASA P400"}
      看趋势 → {"trend": "YASA轴向磁通电机技术路线"}
→ 合并: 实体"YASA"同时具有竞品属性和技术趋势属性
```

### 4.2 矛盾识别（Conflict Detection）

标记并解释矛盾信息：

```
级别: 矛盾 | 不一致 | 信息不足
示例: 
  "技术成熟期" vs "新入局者增加300%"
  → 解释：全局成熟，局部（低空经济细分）仍处爆发期
```

### 4.3 跨模块关联（Cross-Module Linking）

将孤立发现连接为洞察链：

```
看对手: "YASA 15kW/kg" 
    + 看客户: "需求>12kW/kg"
    + 看自己: "我司10kW/kg"
→ 洞察: 明确Gap，追赶目标清晰
```

### 4.4 优先级排序（Priority Scoring）

对机会点按 `市场吸引力 × 我司胜率` 评分排序。

**输出**: 整合后的结构化洞察数据，直接作为Layer 3的输入。

## 5. 三定决策模块（Layer 3）

顺序执行，每步输出作为下一步输入。

### 5.1 定目标 Agent

**输入**: 交叉验证后的完整洞察数据

**输出**:

```json
{
  "technical_mvp": {
    "指标": [
      {"param": "功率密度", "target": "≥12 kW/kg", "basis": "客户底线(12)+竞品最高(15)的中间值"},
      {"param": "效率", "target": "≥94%", "basis": "行业标杆水平"}
    ],
    "必须认证": ["CAAC适航认证"],
    "mvp_verdict": "一句话总结MVP定位"
  },
  "business_targets": {
    "time_to_market": "18个月",
    "target_cost": "<$50/kW",
    "first_year_sales_estimate": "5000台",
    "break_even_point": "第3年"
  }
}
```

### 5.2 定策略 Agent

**输入**: 定目标的输出

**评估三条路线，推荐其中一条**:

| 路线 | 适用条件 | 推荐例 |
|------|----------|--------|
| **技术领先** | 有核心专利/新材料突破 | "功率密度比YASA高15%" |
| **平替降本** | 国内供应链成熟 | "成本降30%，性能达80%" |
| **蓝海聚焦** | 巨头放弃的细分市场 | "特定功率段/特定认证市场" |

**输出**:

```json
{
  "recommended_strategy": "技术领先 | 平替降本 | 蓝海聚焦",
  "rationale": "推荐理由（引用五看数据支撑）",
  "rejected_strategies": [
    {"strategy": "不推荐的路线", "reason": "为什么不选"}
  ],
  "differentiation_edges": ["差异化优势1", "差异化优势2"]
}
```

### 5.3 定计划 Agent

**输入**: 定目标 + 定策略

**输出**:

```
里程碑:
  M1 (0-3月):  概念验证 (POC) — 关键交付物
  M2 (3-9月):  工程样机 (A Sample) — 关键交付物
  M3 (9-15月): 设计验证 (B Sample) — 关键交付物
  M4 (15-24月): 量产准备 — 关键交付物

Top 3 技术风险:
  1. 风险描述 (影响阶段, 缓解措施)
  2. ...
  3. ...

资源配置建议:
  核心团队规模, 关键设备需求, 外部合作建议
```

## 6. 报告生成器（Layer 4）

### 6.1 双格式输出

报告生成器**同时输出 MD 和 HTML 两种格式**，保存至同一目录，文件名相同仅扩展名不同。

```
输出路径: docs/5s3d-reports/{YYYY-MM-DD}-{产品方向slug}-report.md
                                    {YYYY-MM-DD}-{产品方向slug}-report.html
```

| 格式 | 用途 | 特点 |
|------|------|------|
| **Markdown (.md)** | 原始报告，可Git版本管理、可继续编辑 | 保留完整结构化Markdown |
| **HTML (.html)** | 可直接浏览器打开、适合投屏/分享 | 含CSS样式排版，表格/代码块/引用渲染美观 |

HTML报告中嵌入内联CSS样式（无外部依赖），确保在任何浏览器中打开即有良好的可读性。

### 6.2 报告结构

两种格式共用同一内容模板，按以下结构组织：

```markdown
# 五看三定战略洞察报告：{产品方向}

## 一、摘要（1段话，CEO可读）
## 二、方法论（简要说明五看三定）

## 三、看趋势
### 3.1 技术生命周期
### 3.2 政策与标准

## 四、看对手
### 4.1 竞争格局全景
### 4.2 关键竞品对标表

## 五、看客户
### 5.1 痛点分析
### 5.2 价值主张匹配

## 七、看机会

### 7.2 TAM/SAM/SOM

## 八、交叉验证洞察
### 8.1 跨模块关联发现
### 8.2 矛盾与风险提示
### 8.3 机会优先级排序

## 九、定目标

```

### 6.3 规范表格

竞品对标表使用标准Markdown表格：

```
| 维度 | 行业标杆(YASA) | 黑马(某初创) | 我司(目标) | 胜出概率 |
|------|---------------|-------------|-----------|---------|
| 峰值功率密度 | 15 kW/kg | 12 kW/kg | 14 kW/kg | 中高 |
| 冷却技术 | 槽内油冷 | 壳体水冷 | 直接油冷 | 中 |
| 目标成本 | 极高端 | 中等 | 中偏低 | 高 |
```

### 6.4 风险提示块

重要风险使用Blockquote格式，使其在Markdown中醒目：

```
> ⚠️ **战略风险提示**
> [具体风险描述和依据数据]
```

## 7. 边界情况与错误处理

| 场景 | 处理方式 |
|------|----------|
| **搜索无结果** | Agent输出"未找到相关数据" + 建议可尝试的替代搜索词 |
| **信息不足（如看机会找不到市场规模）** | 标注"数据缺失"，基于已知可比市场做粗估，附说明"仅供参考" |
| **看自己无用户输入** | 输出标准Gap模板，标注"请补充我司能力信息以便精准分析" |
| **网络/工具调用失败** | 重试1次，仍失败则跳过该Agent，报告中标注"此模块因搜索暂时不可用" |
| **输入方向过于宽泛** | 提示用户缩小范围（如"新能源汽车"→"800V SiC电驱系统"） |
| **多Agent结果严重矛盾** | 交叉验证层标记为"高冲突"，同时在报告中并列呈现不同视角 |

## 9. 设计原则回顾

- **YAGNI**: 仅实现5看3定核心功能，不加入协作、版本管理、报告分享等非必要功能
- **隔离性**: 每个Agent职责单一，通过Schema约束接口，可独立修改和测试
- **容错**: 单个Agent失败不影响整体（标记缺失，继续输出）
- **可扩展**: 后续可通过MCP Server接入更多数据源，无需改动Agent逻辑
